| 到起点的 goto 中止后仍继续回放 | 力矩保护不能终止完整流程 | 检查起点运动结果，传递用户配置的力矩阈值，中止后直接返回 |

| 回放轨迹缺少结构和数值检查 | NaN、错误维度或错误时间序列可能进入插值控制 | 运动前验证非空、维度、有限值、严格递增时间戳及正数参数 |

## 后续优先项（本次未修复）

1. `CaptureService.stop_episode()` 自动保存异常被吞掉。需要明确反馈保存失败、保留重试入口，并对原始文件使用临时文件写入后替换，避免磁盘故障造成静默丢失或半文件。
2. `server/app.py` 在模块导入时创建默认服务并启动控制线程，CLI 又创建一次服务。应迁移到应用 lifespan，统一关闭控制循环和相机资源，并增加生命周期测试。
3. 数据集 `info.json` 声明向量字段，但实际 Parquet 使用展开列；仍不是可直接交给 LeRobot v3 的标准数据集。应先确定目标格式版本，再增加转换器和字段级校验。
4. 打包现在保护同名目录，但失败时仍可能留下不完整的新目录；应增加暂存目录发布流程、视频复制失败反馈和数据完整性验证。
5. goto、park、replay 缺少统一的运动任务互斥和取消机制；部分路径同时使用后台控制环与同步 run_steps。需要独立梳理控制线程所有权，并用模拟故障与真机台架验证。

真机验收仍需覆盖力矩超限、冻结、接管、断连、退出归零和实际夹爪标定。本次模拟测试不能替代这些验证。
