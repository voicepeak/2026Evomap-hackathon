# 遥操数据平台 · 黑客松 Demo 方案

> 一句话：**让别人带着"主臂+相机"到处跑采数据的日子结束——用一块数位板/一个手柄，把遥操采数变成人人可做、数据可直接训练。**

---

## 0. 一分钟讲稿（现场照着念）

> 具身智能现在最缺的不是算法，是**真实数据**。
> 但采数据今天很重：要有主臂、要标定、要两个人、要一台 Ubuntu 机器，光把机械臂跑起来就能耗掉一整天。
> 我们做的是——**把"采数据"这件事变成一个消费级体验**：
> 一块数位板（或我们的 6 自由度手柄）控制机械臂，一个采集盒负责录制和质检，数据自动打包成 LeRobot 标准格式，一键就能训练。
> 我们卖的不是机械臂，是**采集工具 + 数据标准**：谁都能在家采数据，采出来的数据可以直接卖给需要它的模型团队。
> 现在演示：**遥操 → 录制 → 质检 → 训练 → 回放**。

## 1. 痛点（为什么是现在）

| 现实 | 具体问题 |
|---|---|
| 采数据门槛高 | 主臂贵、要标定、关节方向/零点/限位一堆坑，非专家根本跑不起来 |
| 环境割裂 | ROS2 / Isaac Sim / LeRobot 默认全在 Ubuntu，macOS 用户被挡在门外 |
| 数据不可用 | 各家用各自的臂、各自的相机、各自的时间戳，数据无法直接互换训练 |
| 没有质量保障 | 采集靠人盯，脏数据混进数据集，训练白跑 |

> 这些都是我们在真实硬件上亲手踩过的（见文末"已验证"）。

## 2. 我们做什么

```
┌─ 输入层 ─────────┐   ┌─ 采集层 ─────────────┐   ┌─ 平台层 ───────────────┐
│ 数位板 (Demo)     │   │ 采集 App             │   │ 数据标准 + 质检评分      │
│ 6-DoF 手柄 (规划) │──▶│ 相机 + 关节同步      │──▶│ 数据集打包(LeRobot 格式) │
│ 手势 (辅助)       │   │ 自动质检 / 打包      │   │ 授权 / 交易 / 一键训练   │
└──────────────────┘   └─────────────────────┘   └────────────────────────┘
        ▲
        └── 安全层：抱闸 + 重力平衡 + UPS + 急停 + 安全状态机
```

**三层价值**

- **工具层**：让采数据变简单（数位板遥操 + 自动配置 + 安全兜底）
- **标准层**：数据带标定、带时间戳、带质量分，**下载即训**
- **市场层**：数据可授权、可溯源、可交易

## 3. Demo 演示什么（现场 5 分钟）

| 步骤 | 操作 | 屏幕/机械臂上看到什么 |
|---|---|---|
| ① 连接 | 插上数位板 + 采集盒，点"开始" | 自检通过：7 个电机在线、状态灯绿 |
| ② 遥操 | 用笔拖动，机械臂跟着走；笔按住=跟手，抬笔=悬停 | 机械臂末端平滑跟随，姿态不抖不坠 |
| ③ 录制 | 按一下录制键，完成 3 次"抓取-放置"，再按停 | 面板显示 episode 01/02/03，成功/失败标记 |
| ④ 质检 | 点"打包" | 自动报告：丢帧 0.4%、限位占用 0%、平滑度 A、质量分 92 |
| ⑤ 训练 | 点"一键训练" | 后台跑 ACT，日志滚动，曲线下降 |
| ⑥ 回放 | 点"部署评估" | 机械臂自己复现刚才的动作，**成功率 xx%** |

> **全场只需要屏幕 + 机械臂 + 一块数位板**，不讲代码。

## 4. 技术亮点（评委问答用）

1. **数位板遥操**：绝对坐标 + 笔压 + 落笔离合，200 Hz 控制环、重力前馈、限速与工作空间裁剪 —— 比"主臂直连"便宜一个数量级，比手势稳得多
2. **安全状态机**：只有 park 位允许失能、切模式先加载力矩、断电抱闸兜底 —— 实测过"被打断后失能掉落""切模式 0.5s 空窗下坠"两次事故，全部有对策
3. **一键配置**：电机 ID、方向符号、零点、限位、MIT 增益自动生成，用户永远不用手写参数
4. **数据标准**：LeRobot 格式 + 扩展（相机内外参、硬件序列号、时间戳、质量分、授权、签名）
5. **溯源与授权**：安全芯片签名 manifest，买家可验证"数据来自标定过的设备、未被篡改"

## 5. 数据长什么样

| 类别 | 字段 |
|---|---|
| 轨迹 | 7×关节 pos/vel/torque、夹爪 pos/force、动作序列 |
| 相机 | wrist + 2 路固定，30 fps，**每帧硬件时间戳** |
| 硬件 | 臂型号/序列号、电机型号（RS06×3 / RS00×4）、方向、限位、kp/kd |
| 标定 | 零点、相机内外参、标定哈希 |
| 任务 | 语言指令、物体标签、成功/失败、episode 边界 |
| 质量 | 平滑度、丢帧、限位占用、成功率 |
| 授权 | 训练/商用/独占、期限、签名 |

**核心差异**：别人的数据是"视频+关节角"；我们的数据是**可训练的、可验证的、可交易的数据包**。

## 9. 评委可能问的问题（预备答案）

**Q：为什么不用 VR / 手柄 / 键盘遥操？**
A：都能做，但我们要的是"绝对坐标 + 低延迟 + 不依赖算法稳定性"。数位板是被验证过的绝对输入，手势在真实光照下不稳定（我们实测过）；未来换成自研 6-DoF 手柄，并加力反饋。

**Q：数据凭什么值钱？**
A：值钱的不是"演示视频"，是**带标定、带同步时间戳、带质量分、带授权**的可训练数据包。我们卖的是"下载即训"，不是"一堆文件"。

**Q：大厂自己采怎么办？**
A：他们采不完垂类场景。我们的定位是"跨品牌的一层 + 标准与质量"，谁采都行，但用我们的标准交付。

**Q：硬件会被抄吗？**
A：外观会，但**安全体系、出厂标定、质量评分、数据网络**抄不走；这些是运营积累。

**Q：安全吗？**
A：三道防线：固件级状态机（非 park 位禁止失能）、硬件抱闸 + 重力平衡 + UPS、急停。我们在真机上出过事故并已修复验证。
