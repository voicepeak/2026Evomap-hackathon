# 具身智能数据采集平台 · 方案 v1.0

> **平台代号**：RDP（Robotic Data Platform，可替换）  
> **一句话**：把"用机械臂采数据"变成一条**标准流水线**——设备自动配置、采集自动质检、数据自动打包成可训练、可授权、可交付的数据集。  
> **基础**：已跑通 B601-RS 数位板/手势遥操 + IK + 重力补偿 + 安全状态机；已有 `tablet_teleop`（WebSocket 笔事件桥 + Web UI）

## 1. 设计目标与原则

**目标**：让一个非专家，在 10 分钟内完成"连接机械臂 → 遥操 → 录一组可训练的数据"。

**五条设计原则**

| 原则 | 含义 |
|---|---|
| **本地优先** | 采集端全部本地跑（无网可用），上传可选、断点续传。演示与真实入户都成立 |
| **标准输出** | 产出一律是 LeRobot 数据集（Parquet + MP4 + meta），不发明私有格式 |
| **质量前置** | 不合格的 episode 在采集端就标红，脏数据**不允许**进入平台 |
| **可溯源** | 每条数据自带设备指纹、标定哈希、时间戳、授权记录、签名 |
| **硬件中立** | 输入设备（数位板/手柄/手势）与机械臂（B601/SO-101/OpenArm）都通过适配层接入 |

**关键非目标（本阶段不做）**

- 不做通用云平台/复杂账号体系
- 不做实时多人协作采集
- 不做数据"竞价/拍卖"这类交易机制

## 2. 平台全景架构

```
┌────────────────────────────── 采集端（本地，离线可用） ──────────────────────────────┐
│                                                                                    │
│  输入设备            采集服务（Python / FastAPI + WS）            本地存储            │
│  ├ 数位板  ──┐      ├ 遥操通道（200Hz 控制环）                   ├ SQLite（元数据）   │
│  ├ 手柄    ──┼────▶ ├ 安全状态机 / 重力前馈 / IK                 ├ episodes/          │
│  └ 手势    ──┘      ├ 录制引擎（episode 切分 / 丢弃 / 重录）      │   ├ cam/*.mp4      │
│                     ├ 质量门（实时指标 + 评分）                   │   ├ joint.parquet  │
│  机械臂 ◀── CAN ────┤ 打包器（LeRobot 数据集）                    │   └ meta.json      │
│  相机   ◀── 触发 ───┤ 上传器（断点续传）                          └ 缓存/              │
│                     └ Web UI（浏览器打开，零安装）                                   │
└──────────────────────────────────────┬─────────────────────────────────────────────┘
                                       │ HTTPS（可选、可延迟）
┌──────────────────────────────────────▼─────────────────────────────────────────────┐
│                              云端平台（轻量）                                        │
│  ├ 设备注册 / 健康 / 固件版本        ├ 数据集仓库（版本 / 统计 / 预览）              │
│  ├ 任务派发（任务卡 / 进度 / 结算）  ├ 授权与交付（授权范围 / 订单 / 下载）          │
│  ├ 质量复核 + 人工抽检               ├ 签名校验 + 指纹去重 + 审计日志               │
│  └ 运营看板（设备 / 数据 / 收入）    └ 买家端页面（预览 / 试训报告 / 下单）          │
└────────────────────────────────────────────────────────────────────────────────────┘
```

**一句话理解**：**采集端是"能离线干活的设备"**，**云端是"账本和货架"**。断网也能采，连网再交货。

## 3. 角色与权限

| 角色 | 能做什么 | 关键约束 |
|---|---|---|
| 采集者（Operator） | 领取任务、遥操采集、提交 episode | 只能看自己的数据；授权范围需本人确认 |
| 采集团队管理员 | 管理设备/成员、分配任务、查看质量分 | 不能改授权与价格 |
| 平台审核（QA） | 抽检、评级调整、驳回、封禁设备 | 所有操作留审计日志 |
| 数据买家 | 预览、验证、下单、下载 | 只能按授权范围使用，密钥下载+水印 |
| 运维/管理员 | 设备、固件、账号、结算 | 双人复核敏感操作 |

## 4. 功能模块

### 4.1 设备管理
- 注册与绑定：设备序列号 + 公钥（生产用安全芯片，MVP 用本地密钥文件）
- 健康检查：7 电机在线、故障码、电压/温度、CAN 误码、相机枚举
- 固件/配置版本记录；一键诊断报告（导出给客服）

### 4.2 配置与标定（消灭手工参数）
- 设备档案 → **自动生成**：电机 ID（1–7）、型号（RS06×3 / RS00×4）、方向符号、零点、软限位、MIT kp/kd、`limit_torque`、`loc_kp/spd_kp/acc_rad/vel_max`
- 标定向导：摆零位 → 一键校零 → 回读校验 → 写标定文件（含哈希）
- 异常恢复：自动 `clear_error`、限位越界告警、方向自检（左右手规则）

### 4.3 采集端 App（浏览器 UI + 本地服务）
- 遥操：数位板/手柄/手势三通道，落笔离合、限速、工作空间裁剪
- 录制：开始/停止/丢弃/重录，自动切分 episode，成功/失败标记，语音打标（可选）
- 实时质量灯：速度、抖动、限位占用、丢帧、相机遮挡
- 离线缓存与断点续传；采集模式（单人/团队）

### 4.4 数据管道
- 上传（分片、断点续传、校验和）→ 转码/校验 → 元数据抽取 → 入库
- 硬件时间戳对齐（关节状态与相机帧共用时钟）
- 去重：轨迹哈希 + 特征相似度；隐私：人脸/屏幕模糊（可选）

### 4.5 质量与评分
- 规则引擎（见 §7）：硬门（丢帧/限位/成功标记）+ 软指标（平滑度/覆盖度）
- 评分卡 → A/B/C 分级；C 级仅可用于预训练，不可上架
- 人工抽检工作台（随机抽样 + 争议复核）

### 4.6 数据集管理
- 从 episode 组集：按任务/场景/操作者/时间筛选
- 版本管理（v1、v1.1 增删了哪些 episode）
- 一键导出：LeRobot 数据集目录 + 统计报告（分布/时长/成功率）
- 发布到平台货架 / Hugging Face（作为可信通道）

### 4.7 授权与交付
- 授权模板：训练用途 / 商用 / 独占（价格梯度）；期限、地域、转售限制
- 交付方式：签名下载包 + 买家密钥水印（可追踪泄漏）
- 订单与结算：抽成比例、对账单、发票接口（预留）

### 4.8 任务系统
- 任务卡：任务描述、物体清单、环境要求、目标条数、质量要求、报酬
- 领取/验收/驳回/重采；进度看板；超时释放

### 4.9 运营与看板
- 设备在线率、日均 episode、质量分分布、买家复购、单条成本
- 审计日志（谁在什么时候改了授权/评级/价格）

## 5. 端到端采集工作流

```
任务卡 ──▶ 设备自检 ──▶ 标定(首次) ──▶ 遥操采集 ──▶ 实时质检
   ▲                                                    │
   │                                              ┌─────▼─────┐
   │                                              │ 合格?      │
   │                                              │ 否→重录    │
   │                                              │ 是→打包     │
   │                                              └─────┬─────┘
   └──── 结算/信誉分 ◀── 审核入库 ◀── 上传(可延迟) ◀──────┘
                                    │
                        组集 ──▶ 授权 ──▶ 买家交付(签名+水印)
```

**关键动作的判定点**

| 动作 | 判定 |
|---|---|
| episode 结束 | 操作者按钮 或 任务完成信号（夹爪开合序列） |
| 合格 | 硬门全过 + 评分 ≥ B |
| 入库 | 上传完成 + 服务端校验哈希一致 |
| 上架 | 审核通过 + 授权信息完整 |
| 交付 | 订单支付 + 授权签署 + 买家密钥水印 |

## 6. 数据标准（Schema）

**基线**：LeRobot dataset v3（Parquet + MP4 + `meta/`），扩展一个 `rebot_meta.json`。

| 类别 | 字段 | 示例 |
|---|---|---|
| 轨迹 | `joint.pos[7]`, `joint.vel[7]`, `joint.torque[7]` | rad / rad·s⁻¹ / N·m |
| 夹爪 | `gripper.pos`, `gripper.force` | m / N |
| 相机 | `cam.wrist.mp4`, `cam.ext1.mp4`, `cam.ext2.mp4` | 640×480 @ 30fps |
| 时间戳 | `t_hw_us`（每帧） | 硬件时钟 |
| 硬件 | `arm_model`, `serial`, `motor_map` | `B601-RS` / `RS06×3+RS00×4` |
| 控制 | `control_mode`, `kp/kd[7]`, `limit_torque[7]` | `MIT` |
| 标定 | `urdf_version`, `zero_offset[7]`, `cam_intrinsics/extrinsics`, `calib_hash` | — |
| 任务 | `instruction`, `objects`, `scene`, `success`, `episode_index` | 语言指令 / 标签 |
| 质量 | `qc.*`, `score`, `grade` | 见 §7 |
| 授权 | `license.scope`, `expiry`, `region` | `train` / `commercial` / `exclusive` |
| 溯源 | `manifest_ed25519`, `device_pubkey`, `uploader_id` | 签名 |

> **原则**：任何一条数据都能回答三个问题——**从哪台设备来、标定状态如何、谁能用它**。

## 7. 质量门与评分卡

### 7.1 硬门（任一不满足 → 不合格，禁止入库）

| # | 规则 | 阈值 |
|---|---|---|
| 1 | 丢帧率 | < 2% |
| 2 | 关节限位占用时间 | < 5% |
| 3 | 相机帧数 = 标称帧数（±1%） | 完整 |
| 4 | 时间戳连续性 | 无跳变 > 50 ms |
| 5 | 成功标记 | 必须为"成功"（采集时确认） |
| 6 | episode 时长 | 1–120 s |
| 7 | 标定哈希一致 | 与设备档案匹配 |

### 7.2 评分卡（满分 100）

| 维度 | 权重 | 指标 |
|---|---|---|
| 平滑度 | 30 | 关节 jerk 分布、末端速度波动 |
| 完整性 | 25 | 任务覆盖（物体/位置多样性）、时长合理度 |
| 同步质量 | 20 | 相机-关节时间对齐误差、丢帧 |
| 安全 | 15 | 限位占用、峰值电流、温度 |
| 隐私/合规 | 10 | 无敏感画面（或已模糊处理）、授权完整 |

**分级**：A ≥ 85（可直训）｜B 70–85（轻清洗）｜C < 70（仅预训练，不上架）

> 评分不是"扣分制"而是"质量信号"：买家看到 A 级就知道"下载即训"。

## 8. 数据模型

> MVP 用 SQLite，云端用 Postgres；字段同名迁移。

| 表 | 关键字段 |
|---|---|
| `users` | id, name, roles[], contact |
| `devices` | id, serial, arm_model, motor_map(json), fw_version, calib_hash, pubkey, status |
| `tasks` | id, title, spec(json), target_episodes, requirements, payout, status |
| `sessions` | id, device_id, task_id, operator_id, start_at, end_at, config(json) |
| `episodes` | id, session_id, duration_s, frames, cameras[], success, qc(json), score, grade, files(json), manifest_hash, signature, status |
| `datasets` | id, name, task_id, episode_ids[], schema_version, size_bytes, stats(json), license_default, published_at |
| `licenses` | id, dataset_id, buyer_id, scope, expiry, region, price, status |
| `orders` | id, buyer_id, dataset_id, license_id, amount, paid_at, delivery_url, status |
| `audit_logs` | id, actor, action, target, before, after, at |
| `payouts` | id, operator_id, task_id, episodes[], amount, status |

**关系**：`device → session → episode* → dataset → license → order`（一条链，方便审计与分账）。

## 9. API 草案

### 采集端（本地服务，`127.0.0.1:8765` 起）

| 方法 | 路径 | 说明 |
|---|---|---|
| WS | `/teleop` | 输入设备样本流（数位板/手柄/手势） |
| GET | `/device/status` | 电机/相机/温度/故障/标定状态 |
| POST | `/session/start` | 开一次采集会话（带 task_id） |
| POST | `/session/stop` | 结束会话 |
| POST | `/episode/start` / `/episode/stop` | 手动切分 episode |
| POST | `/episode/discard` | 丢弃当前 episode |
| GET | `/episode/list` | 本地 episode 列表 + 质量分 |
| POST | `/pack` | 打包 LeRobot 数据集（本地目录） |
| POST | `/upload` | 上传（支持断点续传） |

### 云端

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/devices/register` | 设备注册（序列号 + 公钥） |
| GET | `/tasks` / POST `/tasks/{id}/claim` | 任务列表 / 领取 |
| POST | `/episodes` | 上传 episode（multipart + 哈希） |
| GET | `/episodes/{id}` | 元数据 + 质量报告 |
| POST | `/datasets` | 组集（episode_ids → dataset） |
| POST | `/datasets/{id}/publish` | 上架（授权信息必填） |
| POST | `/licenses` | 创建授权 / 下单 |
| GET | `/datasets/{id}/download` | 签名下载（含水印密钥） |
| GET | `/stats` | 看板数据 |

**SDK**：`pip install rebot-data` → 采集端可直接 `from rebot_data import CaptureSession`；买家端 `RebotDataset.load(repo_id)`（对齐 LeRobot API）。

## 10. 技术栈与部署

| 层 | 选型 | 备注 |
|---|---|---|
| 采集端服务 | Python 3.10+（uv）+ FastAPI + WebSocket | 复用现有 `tablet_teleop/bridge.py` 思路 |
| 采集端 UI | 浏览器（本地静态页） | 零安装；复用 `tablet_teleop/web/index.html` |
| 控制内核 | `reBotArm_control_py`（Pinocchio + motorbridge） | 已有 IK/重力补偿/安全补丁 |
| 存储（本地） | SQLite + 文件目录 | 断网可采 |
| 打包 | pyarrow（Parquet）+ ffmpeg | LeRobot v3 结构 |
| 签名 | Ed25519（cryptography） | MVP 用本地密钥，生产用安全芯片 |
| 云端 | FastAPI + Postgres + Redis(RQ) + MinIO/S3 | Docker Compose 起步 |
| 前端 | Next.js / Vue | 买家端 + 运营看板 |
| 部署 | 采集端：一键脚本；云端：单机 Docker | 小团队不碰 K8s |
| 相机 | UVC（免驱）优先，可选 D405 腕部 | 硬件触发可选 |

## 11. 安全、隐私与合规

| 项 | 措施 |
|---|---|
| 设备身份 | 每台设备一对密钥；生产用 ATECC608A/SE050 |
| 数据完整性 | 上传校验和 + manifest 签名 + 标定哈希比对 |
| 防泄漏 | 买家下载包内嵌买家密钥水印；指纹可追踪 |
| 隐私 | 采集端可选人脸/屏幕模糊；镜头硬件开关；录制指示灯；音频默认关闭 |
| 授权 | 采集者在录制时的授权选择会写入 manifest，事后不可静默修改（审计留痕） |
| 审计 | 授权/评级/价格变更全部双人复核 + 日志 |
| 免责 | 采集端安全规范（1 m 距离、禁止热插拔、70% 臂展）+ 用户确认 |

## 12. 与现有代码资产的对应关系

| 现有资产 | 在平台中的角色 | 改造量 |
|---|---|---|
| `tablet_teleop/bridge.py`（WS 笔事件 + 环形缓冲 + CSV） | 采集端 **输入通道 v0** | 小：加"下发到控制环"的 sink |
| `tablet_teleop/web/index.html` | 采集端 **UI 起点** | 中：加录制/质检/任务面板 |
| `reBotArm_control_py`（IK/重力/安全补丁） | 采集端 **控制内核** | 小：包一层 CaptureSession |
| 已有安全补丁（`clear_error`、`skip_disable`） | 安全状态机一部分 | 小：移到采集服务 |
| 实测电机参数（ID/方向/限位/kp/kd） | 自动配置生成器数据 | 小：写成 device profile |
| LeRobot（上游）+ motorbridge SDK | 数据格式 + 电机协议 | 直接用 |

> **结论**：采集端 = `tablet_teleop` + `reBotArm_control_py` + 录制/质检/打包层。不需要重写。

## 14. 风险与开放问题

| 风险 | 对策 |
|---|---|
| 采集端环境差异（macOS/Ubuntu/驱动） | gs_usb 免驱适配器 + Edge 盒镜像 + 一键脚本 |
| 质量门太严 → 采集者挫败 | 门只卡"硬伤"；软指标做提示不做拦截；给"如何变好"的实时反馈 |
| 隐私争议 | 默认关闭音频、模糊可选、指示灯、授权写入 manifest |
| 数据卖不动 | 平台先服务"代采 + 授权"，Marketplace 放 v2 |
| 单人操作太慢 | 支持"批量任务 + 半天一采"的作业模式；后续评估双人协作 |

**开放问题**

1. 授权默认档位：非独占（走量）还是独占（高价）？
2. 质量分由谁最终负责：算法评分 or 人工抽检（比例）？
3. 结算货币/账期：先只做人民币、T+7？
4. 是否允许采集者自带机械臂（只买输入设备）？——建议允许，扩大设备安装量。
